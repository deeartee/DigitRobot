CNN для распознавания цифр 0–9 по изображению 28×28 (grayscale).

## Файлы
- `config.py`       — параметры запуска (эпохи, батч, lr, пути, размеры)
- `synth_digits.py` — синтез датасета цифр
- `conv_model.py`   — модель `DigitConv`
- `runner.py`       — обучение → `model.pt`, загрузка чекпойнта
- `app.py`          — предсказание (CLI)

## Как это работает

Пайплайн состоит из четырёх шагов: генерация данных → обучение →
сохранение → инференс.

### 1. Генерация датасета (`synth_digits.py`)
Функция `make_dataset(per_digit, seed)` создаёт синтетические изображения
цифр 0–9. Для каждой цифры:
- на холсте 56×56 рисуются отрезки из словаря `SEGMENTS` (грубый «скелет»
  цифры линиями разной толщины);
- применяется лёгкое размытие (сглаживание краёв);
- случайный поворот в диапазоне ±12° и сдвиг до ±3 пикселей;
- изображение обрезается по bounding box содержимого, масштабируется до
  20×20 и центрируется на холсте 28×28;
- добавляется гауссов шум (σ=0.03) и значения клиппируются в [0, 1].

На выходе: `X` формы `(N, 1, 28, 28)` float32 и `y` формы `(N,)` int64,
где `N = 10 * per_digit`. По умолчанию `per_digit = 300`, то есть 3000
примеров. Seed фиксирован (`42`) для воспроизводимости.

### 2. Модель (`conv_model.py`)
`DigitConv` — небольшая свёрточная сеть:
- Conv(1→16, 3×3, padding=1) → ReLU → MaxPool(2) → тензор 16×14×14
- Conv(16→32, 3×3, padding=1) → ReLU → MaxPool(2) → тензор 32×7×7
- Flatten → Linear(32·7·7 → 128) → ReLU → Dropout(0.3)
- Linear(128 → 10) — логиты по классам 0–9

Параметров около 420 тыс. — хватает для 28×28, обучается быстро даже на CPU.

### 3. Обучение (`runner.py`)
Функция `train()`:
- генерирует датасет и делит его на train/val в пропорции 80/20
  (`VALIDATION_SHARE = 0.2`) со случайным перемешиванием (seed=0);
- оборачивает выборки в `TensorDataset` и `DataLoader`
  (batch = 128, train перемешивается, val — нет);
- создаёт модель, `CrossEntropyLoss`, `Adam(lr=1e-3)` и `StepLR`
  (уменьшает lr вдвое каждые 8 эпох);
- в каждой эпохе: один проход по train с backprop, затем проход по val
  без градиентов; печатает loss, train_acc, val_acc;
- если val_acc улучшился — сохраняет чекпойнт в `model.pt` как словарь
  `{state, best_val, epoch, config}`; иначе увеличивает счётчик
  «без улучшений»;
- после `PATIENCE = 5` эпох без улучшения — early stopping.

Функция `load_trained()` читает `model.pt`, восстанавливает архитектуру,
загружает веса и переводит сеть в режим `eval()`. Если файла нет —
бросает `FileNotFoundError` с подсказкой запустить `train`.

### 4. Инференс (`app.py`)
CLI с двумя режимами:

- `python app.py train` — запускает `train()`, создаёт `model.pt`.
- `python app.py predict --demo` — генерирует маленький свежий датасет
  (5 примеров на цифру, seed=7), прогоняет через модель и печатает
  для каждого примера: истинную метку, предсказание и уверенность
  `p = max(softmax)`.
- `python app.py predict img1.png img2.png` — для каждого файла:
  конвертирует в grayscale, ресайзит до 28×28, при необходимости
  инвертирует (если средняя яркость > 0.5, считается что цифра тёмная
  на светлом фоне), прогоняет через модель и печатает предсказанный
  класс и уверенность.

### Что важно знать
- Всё обучение идёт на **синтетических** цифрах. Модель хорошо выучит
  распределение генератора, но на реальных рукописных цифрах или MNIST
  точность будет заметно ниже — это ограничение данных, а не кода.
- Seed зафиксирован и в `make_dataset`, и в сплите, поэтому запуски
  воспроизводимы.
- Чекпойнт — словарь с метаданными; на PyTorch ≥ 2.6 при загрузке
  может понадобиться `weights_only=False` (если увидишь
  `UnpicklingError`).
- Устройство выбирается автоматически: CUDA, если доступна, иначе CPU.
